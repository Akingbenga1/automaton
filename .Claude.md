# Automated Job Application System - Claude Development Guide

## Project Overview

Build an intelligent, automated job application system for the UK tech job market that:
- Applies to jobs automatically across multiple UK job boards
- Maintains rate limits (5 applications per hour by default)
- Uses browser automation to fill applications realistically
- Filters jobs intelligently based on profile matching
- Tracks all applications in a database
- Follows SOLID principles throughout

## Target User Profile

- **Professional Level**: Mid to Senior level tech professional with MBA
- **Target Market**: UK tech job market
- **Target Roles**: Software Engineer, Tech Lead, Engineering Manager, Product Manager, Technical Program Manager, CTO positions
- **Key Requirements**: 
  - Must handle both technical and business/leadership roles
  - Must respect UK job market norms (notice period, right to work, etc.)
  - Must support hybrid/remote preferences

## Supported Job Platforms

### Primary Platforms (Build these first):
1. **LinkedIn UK** - Most important, highest quality
2. **Indeed UK** - Largest volume
3. **CWJobs** - Tech-specific UK platform
4. **Reed.co.uk** - Major UK job board
5. **Technojobs** - IT/Tech specialized

### Secondary Platforms (Optional enhancements):
6. **CV-Library** - Profile-based
7. **Adzuna** - Aggregator
8. **ITJobBoard** - Niche IT board

## Core Requirements

### 1. Architecture Principles

**SOLID Principles (CRITICAL):**
- **Single Responsibility**: Each class/module has ONE job
  - Example: `JobScraper` only scrapes, `ApplicationSubmitter` only submits
- **Open/Closed**: Extendable without modification
  - Example: Add new job platforms via interface without changing core code
- **Liskov Substitution**: Platform adapters interchangeable
  - Example: Any `JobPlatformAdapter` can replace another
- **Interface Segregation**: Specific interfaces for specific needs
  - Example: `ISearchable`, `IApplicable` separate from `IJobPlatform`
- **Dependency Inversion**: Depend on abstractions, not concretions
  - Example: Core depends on `IJobPlatform` interface, not `LinkedInAdapter`

**Design Patterns to Use:**
- **Strategy Pattern**: Different application strategies per platform
- **Factory Pattern**: Create platform adapters
- **Observer Pattern**: Application status notifications
- **Repository Pattern**: Data access layer for database
- **Adapter Pattern**: Wrap each job platform's unique interface

#### B. Platform Interface (`src/core/interfaces.py`)

```python
from abc import ABC, abstractmethod
from typing import List, Optional
from src.core.models import Job, Application, Profile

class IJobPlatform(ABC):
    """Base interface all platforms must implement"""
    
    @abstractmethod
    def authenticate(self, credentials: dict) -> bool:
        """Authenticate with the platform"""
        pass
    
    @abstractmethod
    def search_jobs(self, keywords: str, location: str, filters: dict) -> List[Job]:
        """Search for jobs"""
        pass
    
    @abstractmethod
    def apply_to_job(self, job: Job, profile: Profile) -> Application:
        """Apply to a specific job"""
        pass
    
    @abstractmethod
    def get_applied_jobs(self) -> List[Application]:
        """Get list of jobs already applied to"""
        pass
    
    @abstractmethod
    def is_available(self) -> bool:
        """Check if platform is accessible"""
        pass

class IJobMatcher(ABC):
    """Interface for job matching logic"""
    
    @abstractmethod
    def calculate_match_score(self, job: Job, profile: Profile) -> float:
        """Calculate how well a job matches the profile (0.0 to 1.0)"""
        pass
    
    @abstractmethod
    def should_apply(self, job: Job, profile: Profile, threshold: float = 0.7) -> bool:
        """Decide if we should apply to this job"""
        pass

class IRateLimiter(ABC):
    """Interface for rate limiting"""
    
    @abstractmethod
    def can_apply(self, platform: str) -> bool:
        """Check if we can apply to another job on this platform"""
        pass
    
    @abstractmethod
    def record_application(self, platform: str) -> None:
        """Record that an application was submitted"""
        pass
    
    @abstractmethod
    def reset_counters(self) -> None:
        """Reset rate limit counters"""
        pass
```

#### C. Rate Limiter Implementation (`src/scheduler/rate_limiter.py`)

```python
from datetime import datetime, timedelta
from typing import Dict
from src.core.interfaces import IRateLimiter

class HourlyRateLimiter(IRateLimiter):
    """
    Enforces rate limits per platform per hour
    SINGLE RESPONSIBILITY: Only manages rate limiting
    """
    
    def __init__(self, limits: Dict[str, int]):
        """
        Args:
            limits: Dict of platform -> applications per hour
                    e.g., {"linkedin": 2, "indeed": 2, "cwjobs": 1}
        """
        self.limits = limits
        self.applications: Dict[str, List[datetime]] = {
            platform: [] for platform in limits.keys()
        }
    
    def can_apply(self, platform: str) -> bool:
        """Check if we can submit another application"""
        self._clean_old_applications(platform)
        
        if platform not in self.limits:
            return False
        
        current_count = len(self.applications[platform])
        return current_count < self.limits[platform]
    
    def record_application(self, platform: str) -> None:
        """Record a new application"""
        if platform in self.applications:
            self.applications[platform].append(datetime.now())
    
    def reset_counters(self) -> None:
        """Clear all counters (call at hour boundary)"""
        for platform in self.applications:
            self.applications[platform] = []
    
    def _clean_old_applications(self, platform: str) -> None:
        """Remove applications older than 1 hour"""
        if platform not in self.applications:
            return
        
        cutoff = datetime.now() - timedelta(hours=1)
        self.applications[platform] = [
            app_time for app_time in self.applications[platform]
            if app_time > cutoff
        ]
    
    def get_remaining_slots(self, platform: str) -> int:
        """Get how many applications we can still submit"""
        self._clean_old_applications(platform)
        return self.limits[platform] - len(self.applications[platform])
```

import random

from playwright.sync_api import Page

class HumanBehavior:
    """Simulates human-like interactions"""
    
    @staticmethod
    def random_delay(min_seconds: float = 1.0, max_seconds: float = 3.0):
        """Wait a random amount of time"""
        time.sleep(random.uniform(min_seconds, max_seconds))
    
    @staticmethod
    def type_like_human(page: Page, selector: str, text: str):
        """Type text with human-like delays"""
        page.click(selector)
        for char in text:
            page.keyboard.type(char)
            time.sleep(random.uniform(0.05, 0.15))
    
    @staticmethod
    def scroll_slowly(page: Page):
        """Scroll page slowly like a human reading"""
        scroll_amount = random.randint(200, 400)
        page.evaluate(f"window.scrollBy(0, {scroll_amount})")

#### Job Matching Algorithm

```python
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.metrics.pairwise import cosine_similarity
import nltk

class JobMatcher:
    """Intelligent job matching using NLP"""
    
    def __init__(self):
        self.vectorizer = TfidfVectorizer(stop_words='english')
    
    def calculate_match_score(self, job: Job, profile: Profile) -> float:
        """
        Calculate match score between job and profile
        Returns: float between 0.0 and 1.0
        """
        # Combine profile skills and preferences
        profile_text = self._create_profile_text(profile)
        job_text = f"{job.title} {job.description}"
        
        # Calculate similarity
        vectors = self.vectorizer.fit_transform([profile_text, job_text])
        similarity = cosine_similarity(vectors[0:1], vectors[1:2])[0][0]
        
        # Apply bonuses/penalties
        score = similarity
        
        # MBA bonus
        if profile.has_mba and self._mentions_mba(job):
            score += 0.1
        
        # Seniority check
        if not self._appropriate_seniority(job, profile):
            score -= 0.3
        
        # Salary check
        if job.salary_max and job.salary_max < profile.salary_min:
            score -= 0.5
        
        return max(0.0, min(1.0, score))
    
    def _create_profile_text(self, profile: Profile) -> str:
        """Combine profile elements into searchable text"""
        return " ".join([
            profile.current_title,
            *profile.technical_skills,
            *profile.business_skills,
            *profile.leadership_skills,
            *profile.target_roles
        ])
    
    def _mentions_mba(self, job: Job) -> bool:
        """Check if job mentions MBA"""
        keywords = ['mba', 'master of business', 'business degree']
        desc_lower = job.description.lower()
        return any(keyword in desc_lower for keyword in keywords)
    
    def _appropriate_seniority(self, job: Job, profile: Profile) -> bool:
        """Check if job seniority matches profile"""
        junior_keywords = ['junior', 'entry level', 'graduate']
        job_lower = (job.title + " " + job.description).lower()
        
        # MBA holders shouldn't apply to junior roles
        if profile.has_mba and profile.years_experience >= 3:
            return not any(kw in job_lower for kw in junior_keywords)
        
        return True
```

### 8. Running the System

#### Basic Usage

```bash
# Dry run (searches but doesn't apply)
python main.py --dry-run --platforms linkedin,indeed --limit 5

# Real run with manual approval
python main.py --manual-approval --platforms linkedin,indeed --limit 5

# Fully automated run
python main.py --platforms linkedin,indeed,cwjobs --limit 5 --hours 3

# Schedule continuous running
python main.py --continuous --platforms all --limit 5
```

#### CLI Arguments

```
--dry-run: Search and filter jobs but don't apply
--manual-approval: Show each job before applying and ask for confirmation
--platforms: Comma-separated list of platforms (or 'all')
--limit: Applications per hour (default: 5)
--hours: How many hours to run (default: 1)
--continuous: Run indefinitely with scheduler
--verbose: Detailed logging
--config: Path to config file (default: config/profile.yaml)
```

### 10. Safety Features

1. **Dry Run Mode**: Test everything without applying
2. **Manual Approval Mode**: Review each job before submission
3. **Rate Limiting**: Prevents platform bans
4. **Duplicate Detection**: Never apply twice to same job
5. **Error Recovery**: Graceful handling of failures
6. **Logging**: Comprehensive logs of all actions
7. **Screenshots**: Save confirmation screens
8. **Database Backup**: Regular backups of application data

### 12. Legal & Ethical Considerations

⚠️ **Important Warnings:**
- Review each platform's Terms of Service
- Some platforms explicitly prohibit automation
- Risk of account suspension/bans
- Consider limiting to "Easy Apply" / "Quick Apply" only
- Mass applications may harm professional reputation
- Always ensure application quality over quantity

### 13. Success Criteria

**Good Performance Indicators:**
- Response rate > 5%
- Interview rate > 2%
- Low error rate (< 1%)
- Match scores averaging > 0.7
- No platform bans/suspensions

**Red Flags:**
- Response rate < 1% (quality too low)
- Multiple CAPTCHAs (detected as bot)
- Account warnings
- High duplicate application rate

## Final Notes

- **Start with ONE platform** (LinkedIn recommended) and perfect it
- **Test thoroughly** in dry-run mode before going live
- **Monitor response rates** closely and adjust matching algorithm
- **Quality over quantity** - it's better to apply to 5 perfect matches than 50 poor ones
- **Respect rate limits** - aggressive automation leads to bans
- **Keep resumes updated** - outdated info reduces success rate

## Questions to Consider

When implementing, ask yourself:
1. Does this class have a single, clear responsibility?
2. Can I add new platforms without modifying existing code?
3. Are dependencies injected or hard-coded?
4. Is this testable in isolation?
5. Would a junior developer understand this code?

If any answer is "no", refactor before proceeding.
